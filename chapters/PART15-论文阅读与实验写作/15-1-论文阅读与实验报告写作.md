## 3. 实验报告各部分详解

### 3.1 问题提出

**回答：**
- 解决什么问题？背景是什么？
- 现有方法的不足？
- 本文的核心假设？

**模板**：

```markdown
## 1. 问题提出

### 1.1 业务/研究背景
[描述问题来源、重要性、规模]

### 1.2 现有方法
[列出已有哪些方法、效果、限制]

### 1.3 我们的思路
[本文/本实验的核心创新点]

### 1.4 核心假设
[声明本实验成立的前提]
```

**示例**：

```markdown
## 1. 问题提出

### 1.1 背景
工业质检中，电池极片表面缺陷检测依赖人工目检，
效率低（每人 200 件/小时）、漏检率高（5-8%）、劳动强度大。

### 1.2 现有方法
传统方法（边缘检测、模板匹配）难以应对复杂纹理变化。
深度学习方法（YOLOv5）需要大量缺陷样本（数千张），
但实际生产中缺陷样本极少（每年 < 100 张）。

### 1.3 我们的思路
采用"无监督异常检测"（PatchCore），只用正常样本训练，
通过特征空间距离识别异常区域。

### 1.4 核心假设
- 正常样本足够多（5000+ 张）
- 异常区域与正常区域有可区分的特征
- 推理延迟 < 50ms
```

### 3.2 指标选择

**原则**：
- **业务对齐**：指标反映真实业务价值
- **可量化**：有明确计算公式
- **可复现**：数据相同结果应一致
- **多维度**：单一指标有偏

**常见指标**：

| 任务 | 指标 |
|------|------|
| 分类 | Accuracy, Precision, Recall, F1, AUC |
| 检测 | mAP@0.5, mAP@0.5:0.95, Recall, FPS |
| 分割 | mIoU, Dice, Boundary F-score, Hausdorff |
| 跟踪 | MOTA, IDF1, IDSW, FPS |
| 异常检测 | AUROC, AP, Pixel AUROC |
| 生成 | FID, IS, LPIPS |
| 检索 | mAP, Rank-K, MRR |
| NLP | BLEU, ROUGE, METEOR |
| 端到端 | 业务指标 + 性能 + 成本 |

**示例**：

```markdown
## 2. 指标选择

### 2.1 业务指标
- **漏检率** < 3%（不能漏掉真缺陷）
- **误检率** < 1%（避免误报导致产线停摆）

### 2.2 模型指标
- 图像 AUROC > 99%（工业 SOTA）
- 像素 AUROC > 95%（定位精度）

### 2.3 系统指标
- 推理延迟 < 50ms（Jetson Orin Nano）
- 内存峰值 < 4GB（设备限制）
```

### 3.3 数据处理

**记录所有数据相关决策**：

```markdown
## 3. 数据处理

### 3.1 数据来源
[原始数据来源、规模、采集时间]

### 3.2 数据切分
- 训练集：5000 张（仅 normal）
- 验证集：200 张（normal + 各种缺陷）
- 测试集：300 张（normal + 各种缺陷，独立采集）

### 3.3 数据清洗
- 删除模糊图像（曝光异常）
- 删除标注错误样本
- 类别平衡：详见表 X

### 3.4 数据增强
训练集采用：
- 随机裁剪 (224x224, scale 0.08-1.0)
- 水平翻转
- 颜色抖动
- CoarseDropout

### 3.5 数据统计
| 类别 | 训练 | 验证 | 测试 |
|------|------|------|------|
| normal | 5000 | 100 | 150 |
| scratch | 0 | 30 | 50 |
| foil_miss | 0 | 25 | 40 |
| wrinkle | 0 | 20 | 35 |
| particle | 0 | 25 | 25 |
```

### 3.4 模型建立 / 检验

**模型细节需可复现**：

```markdown
## 4. 模型建立与检验

### 4.1 模型选择
基于工业部署约束（边缘 GPU、低延迟），
选择 PatchCore（无监督异常检测 SOTA）。

### 4.2 模型配置
```python
# 完整超参
model = Patchcore(
    backbone='wide_resnet50_2',
    layers=['layer2', 'layer3'],
    coreset_sampling_ratio=0.05,
    num_neighbors=9,
    image_size=224
)
```

### 4.3 训练设置
- 优化器：Adam
- 预训练权重：ImageNet
- 训练轮数：1 epoch（无监督特征提取）
- 批大小：32
- 学习率：1e-3

### 4.4 检验策略
- K 折交叉验证（K=5）
- 独立测试集最终评估
- 多次实验取平均
```

### 3.5 结果解释

**用表格、图表、统计检验**：

```markdown
## 5. 结果解释

### 5.1 主要结果

| 模型 | 图像 AUROC | 像素 AUROC | 延迟 (ms) | 内存 (MB) |
|------|-----------|-----------|-----------|-----------|
| PaDiM | 96.7 | 96.2 | 30 | 1500 |
| PatchCore | **99.6** | **98.1** | 50 | 800 |
| DRAEM | 98.0 | 97.3 | 25 | 2000 |
| EfficientAD | 99.0 | 97.5 | **5** | 500 |

### 5.2 失败案例分析
[图示失败样本，分析原因]
- 细微划痕（< 5px）：当前漏检率 8%
- 多缺陷重叠：当前误检率 4%

### 5.3 消融实验
| 配置 | 图像 AUROC |
|------|-----------|
| ResNet-18 backbone | 98.5 |
| WideResNet-50 backbone | **99.6** |
| + coreset subsampling | 99.4 (faster) |
| + 9 nearest neighbors | 99.6 |

### 5.4 统计显著性
Wilcoxon 检验 p < 0.01，显著优于 baseline。
```

### 3.6 实验总结

**对未来工作的指引**：

```markdown
## 6. 实验总结

### 6.1 核心结论
1. PatchCore 在 MVTec AD 上达到 99.6% AUROC，超过 SOTA
2. WideResNet-50 backbone 比 ResNet-18 提升 1.1%
3. Coreset sampling 不影响精度但提速 5x

### 6.2 局限性
- 推理延迟 50ms，未达 30ms 目标
- 极小缺陷（< 5px）漏检率 8%
- 对训练集分布敏感

### 6.3 未来工作
- 尝试 EfficientAD 降低延迟
- 加入主动学习减少标注
- 部署到 Jetson 实测
- A/B 测试 vs 人工目检
```

## 5. 论文结构（学术版）

### 5.1 学术论文 vs 工业报告

| 维度 | 学术论文 | 工业报告 |
|------|---------|----------|
| **受众** | 研究者 | 工程师/PM |
| **重点** | 新颖性、可复现性 | 业务价值、ROI |
| **实验** | SOTA 对比、消融、消融 | 业务指标、部署可行性 |
| **长度** | 8-10 页 + 补充 | 5-20 页（按需）|
| **风格** | 严谨学术 | 务实工程 |

### 5.2 学术论文标准结构

```mermaid
flowchart TD
  A[Title & Abstract] --> B[1. Introduction]
  B --> C[2. Related Work]
  C --> D[3. Method]
  D --> E[4. Experiments]
  E --> F[5. Conclusion]
  F --> G[References]
  F --> H[Appendices]
```

#### Title & Abstract

- **标题**：简洁、准确、有亮点
- **Abstract**：问题、方法、结果、意义 4 段，150-300 字

#### 1. Introduction

```markdown
### 1. 引言

1. 业务/研究问题
2. 现有方法的局限
3. 本文贡献（3-4 条）
4. 论文结构
```

#### 2. Related Work

按主题分类综述前人工作：

```markdown
### 2. 相关工作

#### 2.1 异常检测
- 传统方法 [Ref1, Ref2]
- 深度学习 [Ref3, Ref4]
- 无监督方法 [Ref5, Ref6]

#### 2.2 工业质检
- 传统视觉检测
- 深度学习在工业的应用
```

#### 3. Method

**核心：图示 + 公式 + 代码**：

```markdown
### 3. 方法

#### 3.1 整体框架
[架构图]

#### 3.2 模块 1：骨干特征提取
[公式 1]、[公式 2]

#### 3.3 模块 2：核心集采样
[公式 3]

#### 3.4 模块 3：最近邻检索
[公式 4]
```

#### 4. Experiments

```markdown
### 4. 实验

#### 4.1 实验设置
- 数据集
- 评价指标
- 实现细节

#### 4.2 与 SOTA 对比
[表格 + 分析]

#### 4.3 消融实验
[消融表]

#### 4.4 定性分析
[成功/失败案例可视化]
```

#### 5. Conclusion

```markdown
### 5. 结论

1. 总结核心贡献
2. 局限
3. 未来工作
```

## 6. 论文阅读方法论

### 6.1 三遍阅读法

```mermaid
flowchart TD
  A[第 1 遍<br/>10 min] --> B[第 2 遍<br/>1 hour]
  B --> C[第 3 遍<br/>半天]
  
  A -->|Title + Abstract + Figures| A1[了解问题]
  B -->|Introduction + Method + Conclusion + 部分 Experiments| B1[理解思路]
  C -->|全文 + 跑代码| C1[完全复现]
```

#### 第一遍（10 min）：鸟瞰

- 读标题、摘要、引言、结论
- 看所有图表和图注
- 列出**不理解的术语**

目标：决定要不要继续读。

#### 第二遍（1 hour）：理解

- 读引言（背景）
- 跳过数学，看方法的高层思路
- 读实验的 SOTA 对比表
- **在关键段落做笔记**

目标：能向别人讲清这篇文章做了什么。

#### 第三遍（半天）：复现

- 完整阅读 + 数学公式
- 对照代码理解实现
- 在自己的数据/任务上复现
- 思考 idea 的局限性

目标：能向别人讲清**为什么有效**。

### 6.2 读论文的常见问题

| 问题 | 解决 |
|------|------|
| 数学看不懂 | 跳过，先看方法概述，Google 不懂的术语 |
| 代码读不懂 | 配合论文 + 简化版开源项目 |
| 实验不可复现 | 检查超参、数据预处理、随机种子 |
| 不知道是不是 SOTA | 查 Papers with Code |

## 9. 常见错误

| 错误 | 后果 | 解决 |
|------|------|------|
| 数据划分有偏 | 结果虚高 | 严格分层抽样 |
| 没说超参 | 不可复现 | 详细记录所有超参 |
| 单次实验 | 偶然性大 | 多随机种子 + 统计检验 |
| 表格单位不一 | 难以比较 | 统一指标格式 |
| 没给失败案例 | 缺乏客观 | 至少 2-3 个失败案例 |
| 引用不严谨 | 学术不端 | 严格按引文规范 |
| 写作模糊 | 难以理解 | 用结构化模板 |

## 本章小结

1. **规范化实验报告** 是 AI 项目可复现、可持续的基础
2. **标准结构**：问题提出 → 指标选择 → 数据处理 → 模型建立 → 结果解释 → 实验总结
3. **实验管理工具**（W&B、MLflow、DVC）大幅提高协作效率
4. **学术论文**重创新、严谨；**工业报告**重业务、可部署
5. **三遍阅读法** 是高效论文阅读的实战技巧
6. **多实验 + 统计检验** 比单次结论更可信
7. **失败案例分析** 是报告客观性的重要体现
8. **可复现性** 是 AI 工作的核心原则之一
