# 16-1 模型评测体系与指标

## 学习目标

- 理解为什么“能训练出来”不等于“能上线”
- 掌握离线评测、人工评测与在线评测的区别
- 了解通用模型与生成式模型的常见指标
- 学会设计可回归、可复现、不过拟合基准的评测集

---

## 1. 为什么要单独讲评测

训练只回答“能不能学到”，评测回答“值不值得用”。

```mermaid
flowchart LR
    A[任务定义] --> B[训练]
    B --> C[离线评测]
    C --> D[人工复核]
    D --> E[小流量上线]
    E --> F[在线监控]
    F --> G[问题回流]
    G --> C
```

评测至少覆盖：

| 维度 | 关注点 |
|---|---|
| 准确性 | 是否答对、是否稳定 |
| 鲁棒性 | 噪声、长尾、对抗输入 |
| 泛化性 | 换数据、换提示词后是否仍可用 |
| 可靠性 | 是否经常胡说、超时、拒答 |
| 成本 | 延迟、吞吐、Token、GPU 占用 |
| 安全性 | 是否泄露敏感信息、是否越权 |

## 2. 三层评测结构

### 2.1 离线评测

固定测试集 + 固定配置，优点是稳定、便宜、可回归。

常见指标：
- 分类：Accuracy、Precision、Recall、F1、AUC
- 回归：MAE、RMSE、R2
- 检索：Recall@K、MRR、nDCG
- 生成：EM、F1、ROUGE、BLEU、CIDEr

### 2.2 人工评测

适合开放式生成任务，常看：
- 正确性
- 完整性
- 相关性
- 可读性
- 有害性

### 2.3 在线评测

- A/B Test
- Canary Release
- Shadow Mode
- 用户满意度
- 任务完成率

---

## 3. 评测常见坑

| 问题 | 说明 |
|---|---|
| 数据泄漏 | 评测集被训练集污染 |
| 只看总分 | 忽略长尾与失败桶 |
| 指标单一 | 准确率高，不代表能上线 |
| 标准不一致 | 人工评测口径不统一 |
| 版本不可复现 | 模型、数据、提示词没记录 |

### 设计原则

1. 测试集固定，不参与训练
2. 保留版本号与标签规则
3. 增加边界样本与长尾样本
4. 做分桶统计，不只看总分

## 4. 最小评测模板

```python
cases = [
    {"id": "easy-1", "input": "解释什么是梯度下降", "gold": "..."},
    {"id": "hard-1", "input": "比较 LoRA 和 QLoRA", "gold": "..."},
]

scores = []
for case in cases:
    pred = model.generate(case["input"])
    scores.append(exact_match(pred, case["gold"]))

print(sum(scores) / len(scores))
```

**建议**：把结果记录成“模型版本 + 数据版本 + 提示词版本 + 指标版本”。
