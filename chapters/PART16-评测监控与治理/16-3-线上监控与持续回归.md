# 16-3 线上监控与持续回归

## 学习目标

- 理解模型上线后为什么会变差
- 掌握数据漂移、概念漂移、质量漂移
- 了解 Canary、Shadow、A/B 等上线策略
- 学会构建持续回归测试

---

## 1. 线上监控要监什么

上线后，模型面对的是变化中的真实世界。

| 指标类 | 例子 |
|---|---|
| 业务指标 | 转化率、完成率、满意度 |
| 模型指标 | 准确率、召回率、拒答率 |
| 系统指标 | 延迟、吞吐、错误率 |
| 成本指标 | GPU、Token、API 费用 |
| 安全指标 | 敏感信息泄露、越权调用 |

### 三种漂移

- **数据漂移**：输入分布变了
- **概念漂移**：标签/规律变了
- **质量漂移**：输出质量下降但分布未必变化

---

## 2. 推荐的上线策略

| 策略 | 作用 |
|---|---|
| Shadow Mode | 先旁路运行，不影响用户 |
| Canary | 只给小流量用户 |
| A/B Test | 比较两个版本效果 |
| Rollback | 出问题快速回滚 |

```mermaid
flowchart LR
    A[新版本模型] --> B[Shadow]
    B --> C[Canary 5%]
    C --> D[扩大流量]
    D --> E[全量发布]
    E --> F[监控告警]
    F --> G[回滚/再训练]
```

## 3. 日志与告警

建议记录：
- 请求输入
- 模型版本
- 提示词版本
- 检索结果
- 工具调用
- 输出结果
- 人工反馈

### 告警阈值示例

| 指标 | 告警建议 |
|---|---|
| 延迟 P95 | 超过基线 30% |
| 错误率 | 超过 1% |
| 拒答率 | 突增 2 倍 |
| 敏感词命中 | 立即告警 |

## 4. 持续回归测试

持续回归就是：每次改模型、改提示词、改检索器，都跑同一批固定测试。

```python
def regression_test(cases, model):
    failed = []
    for c in cases:
        pred = model.generate(c["input"])
        if not c["check"](pred):
            failed.append(c["id"])
    return failed
```

**建议**：
1. 建固定金标集
2. 每次发布前必跑
3. 把失败样本回流到问题库
4. 定期更新测试集，但保留历史版本
