# 16-4 AI 治理与红队测试

## 学习目标

- 理解 AI 治理与风险管理的基本框架
- 了解 NIST AI RMF 的核心思路
- 掌握红队测试与 LLM 安全常见威胁
- 学会上线前的治理清单

---

## 1. 为什么要做治理

模型越强，风险越需要前置管理。

治理不是限制创新，而是让创新能持续、安全、可追责地运行。

### NIST AI RMF 的四个动作

| 动作 | 关注点 |
|---|---|
| Govern | 组织制度、责任、审批 |
| Map | 识别场景、用户、风险 |
| Measure | 量化风险与性能 |
| Manage | 缓解、监控、升级处理 |

---

## 2. LLM / Agent 常见安全风险

参考 OWASP GenAI 风险，可重点关注：

- Prompt Injection
- Insecure Output Handling
- Sensitive Information Disclosure
- Excessive Agency
- Model Theft
- Supply Chain Risk

### 风险示例

Agent 如果能调用工具，就必须限制：
- 能调用什么
- 什么时候调用
- 调用后能不能执行高危动作

---

## 3. 红队测试怎么做

红队测试的目标是主动“找漏洞”。

| 测试项 | 例子 |
|---|---|
| 提示注入 | 诱导模型忽略系统指令 |
| 越权工具调用 | 让 Agent 删除文件、发邮件 |
| 数据泄露 | 诱导输出系统提示词、密钥 |
| 幻觉利用 | 诱导生成错误但看似合理的答案 |
| 社工攻击 | 冒充管理员、客服、审计员 |

### 红队流程

1. 明确资产和边界
2. 列出高风险场景
3. 构造攻击样本
4. 记录成功路径
5. 修复后回归验证
