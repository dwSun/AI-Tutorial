# 图片 PDF 清理设计文档

**日期：** 2026-05-22

## 1. 目标

清理 `assets/figures/` 下当前未被教程正文引用的本地 PDF 图片产物，并修改对应绘图脚本，使其后续默认只生成 PNG，不再额外导出 PDF。

本轮不改教程正文，不调整图片引用路径，不新增新的配图格式约定，只处理“未使用 PDF 产物”这一件事。

## 2. 范围

### 2.1 纳入范围

- `assets/figures/*.pdf`
- 会显式导出 `.pdf` 的 `assets/figures/*.py`
- 对 `README.md`、`SUMMARY.md`、`chapters/**/*.md` 的引用扫描结果

### 2.2 不纳入范围

- 外部论文链接中的 `.pdf`
- Markdown 里普通代码示例中的 `pdf` 字符串
- 非 `assets/figures/` 目录下的其他文件
- 教程正文内容改写

## 3. 备选方案

### 3.1 方案 A（采用）

删除当前未被教程引用的本地 PDF，并去掉脚本中的 PDF 导出逻辑，只保留 PNG 输出。

优点：

- 仓库产物与实际使用保持一致
- 后续重新运行脚本时不会再生成无用 PDF
- 读者和维护者不需要判断双格式是否都必须保留

代价：

- 失去仓库内现成的矢量版导出

### 3.2 方案 B

只去掉脚本中的 PDF 导出，保留仓库里已有 PDF。

问题是历史产物会继续占仓库空间，且容易让人误以为教程仍依赖 PDF。

### 3.3 方案 C

只删除现有 PDF，不改脚本。

问题是后续重新生成图片时会把 PDF 再带回来，不能根治。

## 4. 实施设计

### 4.1 引用判定

先以仓库内 Markdown 为准，确认是否存在对 `assets/figures/*.pdf` 的实际引用。只要正文、目录和 README 都未引用本地 PDF，就将其视为未使用产物。

### 4.2 清理策略

- 删除 `assets/figures/` 中确认未被引用的本地 PDF
- 保留对应 PNG，不改现有 Markdown 的 PNG 引用

### 4.3 脚本调整策略

对当前会额外执行 `savefig(...pdf...)` 的绘图脚本，删除 PDF 输出语句或相关路径变量，只保留 PNG 导出所需的最小逻辑。

如果脚本已经采用 `Path(__file__).resolve().parent` 一类稳定输出目录逻辑，则保持该逻辑不变，只移除 PDF 分支，避免引入与本次目标无关的改动。

## 5. 风险与边界

唯一需要避免的是误删被正文实际引用的文件。因此清理动作以仓库内引用扫描结果为前提，不做“按习惯猜测”的批量删除。

本轮不把“是否应该额外保留 SVG 或其他矢量格式”纳入讨论，避免把简单清理任务扩展成资源规范重构。

## 6. 验收标准

满足以下条件即可视为完成：

- 仓库 Markdown 不引用本地 PDF
- `assets/figures/` 下现有未使用 PDF 已清理
- 原先会额外导出 PDF 的绘图脚本已改为只生成 PNG
- 教程现有 PNG 使用路径保持不变
