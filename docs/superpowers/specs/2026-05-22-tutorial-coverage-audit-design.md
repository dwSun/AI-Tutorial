# 教程覆盖审计与修补设计文档

**日期：** 2026-05-22

## 1. 目标

对 `/home/david/文档/Obsidian/03-Resources/技术/ML-DL` 中的技术类 Markdown 素材做全量扫描，排除明显的资讯、案例、访谈、随笔类文件；再与当前教程仓库中的 `README.md`、`SUMMARY.md` 和 `chapters/**/*.md` 做覆盖比对，找出教程中缺失或覆盖不足的技术点，并直接补充到最接近的现有章节中。

除覆盖性补充外，本轮还同步修复教程中的结构性和质量问题，包括章节编号/标题不一致、目录与正文不同步、事实性错误，以及能通过静态检查定位的 Mermaid 渲染风险。

## 2. 范围

### 2.1 素材侧

扫描 `ML-DL` 目录下的技术类 Markdown，优先纳入以下方向：

- 原理性知识
- 基础网络结构
- 数据处理
- 优化技巧
- 应用领域
- Agent / lmm 中的技术说明类文档
- 其他位于根目录、且明显属于技术说明的 Markdown

排除项：

- 明显的新闻、资讯、访谈、吐槽、随笔
- 案例集合中偏传播型或非技术总结型文档
- `.pptx`、图片和非 Markdown 文件

### 2.2 教程侧

扫描以下内容：

- `README.md`
- `SUMMARY.md`
- `chapters/**/*.md`

必要时同步更新：

- 新增或调整后的章节文件
- `README.md` 中的导航、统计和章节描述
- `SUMMARY.md` 中的目录项

## 3. 产出

本轮工作的最终产出包含三类：

1. 一份内部使用的“素材技术点 -> 教程承载位置”覆盖映射结果
2. 对教程正文的补充与修订
3. 对目录、统计和渲染问题的同步修复

不额外新增对外说明文档；以教程仓库内的直接修订为主。

## 4. 审计与修补方法

### 4.1 技术点抽取

从素材文件中提取以下信息作为候选技术点：

- 文件标题
- 一级、二级标题
- 重复出现的模型名、方法名、任务名
- 与现有教程章节主题明显对应的术语簇

抽取后按主题做归并，例如把“自监督学习 / SimCLR / MoCo”归到自监督与表示学习主题，把“VOC / COCO / 标准化 / 白化 / 归一化”归到数据处理主题。

### 4.2 覆盖判定

每个候选技术点按以下规则判定：

- **已覆盖**：教程中已有独立小节或明确说明，足以支撑读者理解该点的定义、作用和典型用法
- **待增强**：教程中只有点名或一笔带过，缺少关键解释、常见对比或代表方法
- **缺失**：教程中找不到合适承载位置，或相关章节完全未涉及

### 4.3 回填原则

- 优先补到最接近的现有章节
- 同一主题的缺漏尽量合并处理，避免把教程切得过碎
- 只有当一个主题在教程结构中没有自然落点时，才新增“补充阅读”章节
- 新增章节必须同步更新 `SUMMARY.md` 和 `README.md`

## 5. 质量审核规则

### 5.1 结构一致性

检查并修复：

- 文件名、一级标题、目录编号不一致
- `README.md`、`SUMMARY.md` 与正文章节数或标题不一致
- 补充阅读章节是否在导航中完整呈现

### 5.2 内容正确性

检查并修复明显问题：

- 模型演进时间线错误
- 基本概念或术语解释错误
- 不同章节对同一概念的说法明显冲突
- 明显的复制残留或章节标题错位

### 5.3 Mermaid 风险

静态检查并修复常见 Mermaid 问题：

- 代码围栏未闭合
- 图类型声明不规范
- 节点文本包含易破坏解析的未转义字符
- 子图、连线、注释写法导致的常见语法失败
- 同一文件中图块排版异常，影响 Markdown 渲染

不做截图级视觉校验；本轮只处理可通过源码识别的高概率渲染失败问题。

## 6. 改动边界

本轮仅处理与“素材覆盖性审计 + 教程质量修复”直接相关的内容，不顺带扩写无关章节，不重构整套教程结构，不重写教程文风。

补充内容需要延续现有教程的风格：面向系统入门到进阶读者、用语直白、强调概念、原理、代表方法和应用场景。

## 7. 验收标准

满足以下条件即可视为完成：

- 素材中的核心技术点都有归宿：已覆盖、已增强或已补入
- 本轮识别出的明确缺漏已补齐
- 已发现的明显编号/标题/目录错误被修复
- 已发现的高概率 Mermaid 渲染问题被修复
- `README.md`、`SUMMARY.md` 与正文保持一致
